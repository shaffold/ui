# shaffold

**Scaffold a complete, self-owned design system — docs, registry, and library — on top of [shadcn/ui](https://ui.shadcn.com).**

shaffold (shadcn + scaffold) is a fork of shadcn/ui turned into a **one-time scaffolder**, like `create-next-app` but for design systems. You pick a **base × style × color × font**, and shaffold generates:

- a **docs site** whose own chrome renders in the components it documents,
- a **shadcn-compatible registry**, so the official `shadcn` CLI, MCP, and skills work against your design system for free,
- **blocks and examples**, and
- optionally, a **publishable npm library** for teams that want to lock the design.

Then you **detach**. The output is standard, self-owned code with **zero lock-in** — no runtime dependency on shaffold, fully consumable by the official shadcn tooling.

## Why shaffold

- **Scaffold once and detach.** shaffold's job is the initial scaffold. After that, the contract to shaffold is broken — you own the code, and nothing points back at us.
- **Curated component host.** We hand-pick the best components across the shadcn ecosystem into a curated registry, so you get quality components without waiting for them to land upstream.
- **Fully shadcn-compatible.** The scaffolded registry is a standard shadcn registry, so `shadcn add`, `shadcn mcp`, and the shadcn skill all work with no extra server to run.

## What you get

| Piece | Description |
| --- | --- |
| **Docs site** | A [fumadocs](https://fumadocs.dev) site rendering in your design system's own components, with live component previews and syntax-highlighted code tabs. |
| **Registry** | `public/r/**` — a shadcn-compatible registry (`registry.json` + index) built by the official `shadcn build`, so `shadcn add @your-ds/button` just works. |
| **Blocks & examples** | Portable blocks and the examples used to showcase each component in the docs. |
| **Private registry** | Optional token-authenticated registry route for private/internal design systems. |

## Two ways to ship your design system

The same source produces **both** distribution models — pick per team, or offer both:

| | **shadcn registry** (copy) | **npm library** (locked) |
| --- | --- | --- |
| Consume | `shadcn add @your-ds/button` → source copied in | `npm install @your-ds/ui` → `import { Button }` |
| Ownership | consumer owns & edits the code | consumer imports; design is locked |
| Runtime dep | none | yes (the package) |
| Design | drifts (each app diverges) | versioned & centrally updated |
| Best for | teams that want to own/customize | teams that want consistency & control |

The library is generated by `scripts/build-package.mts` and compiled with `tsc` (preserving per-file `"use client"`). CSS strategy is your choice — **precompiled** (self-contained, no consumer Tailwind) or **source** (consumer's Tailwind scans the package).

## How it works

One source of truth — `registry/ui` — and everything else is **derived**, so switching base/style re-derives the whole output instead of drifting hand-maintained copies.

- **Styles** are built locally from a style's CSS (via shadcn's `transformStyle`), so `nova` ships prebuilt and other styles — including community-contributed ones — are built at scaffold time.
- **The registry** is generated from `registry/ui` + blocks + examples, deriving dependencies from real imports.
- **The library** rewrites the app aliases to package-relative imports and packages the same components for npm.

## Repository structure

```
apps/v4/               shaffold's own platform docs (base-nova)
packages/shadcn/       the CLI (fork of shadcn's) — adds the `docs` scaffolding template
templates/docs-app/    the template that gets scaffolded (docs + registry + library)
packages/react/        shadcn internals (styles, presets)
```

## Relationship to shadcn/ui

shaffold is a **fork of [shadcn-ui/ui](https://github.com/shadcn-ui/ui)** and builds directly on its internals (the style-build system, presets, and CLI). We track upstream via a Git remote and merge improvements as they land. All credit for the underlying component system and design goes to [shadcn](https://github.com/shadcn) and the shadcn/ui contributors.
